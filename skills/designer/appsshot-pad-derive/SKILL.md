# 앱스샷 사이즈 대응 — 폰 디자인(6.5" 또는 5.5") 기준으로 패드(iPad) 만들기

> 원본은 `routinery-v2` 레포의 `.claude/rules/appsshot-pad-derive.md`. 여기 사본은 대시보드 공개용이다.

**"6.5 기준으로 패드 맞춰줘" / "5.5 기준으로 패드 맞춰줘"** 요청을 받았을 때 처음부터 끝까지 이대로 한다.
폰 행 하나가 확정된 뒤, 같은 컷 구성으로 **2048×2732 패드 행**을 새로 만드는 절차다.

**기준 폰 사이즈는 6.5"든 5.5"든 상관없다.** 디자이너가 먼저 끝낸 쪽을 기준으로 삼고 절차는 똑같다.
달라지는 건 배율뿐이고, 배율은 1장 공식으로 기준 프레임에서 계산한다.
아래 본문의 "기준 폰"은 6.5"·5.5" 중 고른 쪽을 말한다.

> 2026-10-01 `26Y3Q-Renewal`(v.Blue) 패드 11컷을 **6.5" 기준**으로 이 방식으로 만들었다.
> 표의 예시 숫자는 그때 실측값이다. **디자인이 바뀌면 0장의 실측부터 다시 한다.**
> 폰 사이즈끼리 맞추기(6.5↔5.5)는 맨 아래 「폰 사이즈끼리 맞추기」.

관련: 언어 대응 → `/appsshot-i18n` 스킬 · 코드에서 화면 그리기 → `/appsshot-code-to-figma-draw` 스킬

## 핵심 아이디어 — 한 줄 요약

**폰 목업을 키우지 않는다. 기존 패드 목업 틀은 그대로 두고, 그 안의 앱 UI만 패드 폭(1720×2406)으로 다시 그려 넣는다.**

- 패드 화면 비율(0.75)이 폰(0.46)과 달라서 폰 목업을 키우면 화면이 크게 남거나 잘린다.
- 기준 폰의 앱 UI가 **오토레이아웃 프레임**이면, 균일 축소 후 폭만 늘리는 방식으로 패드 UI를 바로 만들 수 있다.
  기준 폰과 내용(날짜·항목·문구)이 정확히 같아진다.
  6.5" UI(폭 1159 등)든 5.5" UI(폭 1045 등)든 파생 함수가 `ui.width/360` 으로 알아서 맞춘다.
- 배경·헤드라인·뱃지·오버레이(떠 있는 카드·칩·시트)는 기준 폰 노드를 **복제해서 크기만 바꾼다.**

## 1. 패드 캔버스 배치 규격 (2048×2732)

**배율은 기준 폰에서 계산한다.** 패드 헤드라인 목표가 fs150 이므로 기준이 되는 배율은 `H = 150 / fs0` 다.

| 요소 | 기준 폰 → 패드 배율 | 6.5" 기준 실측 (fs0=110) | 위치 |
|---|---|---|---|
| 배경 | 기준 폰 프레임 `fills` 그대로 복사 (그라디언트 포함) | — | — |
| 헤드라인 | `rescale(H)` → **fs150**, 월계관 컷은 폭 2048 로 `resize` | 1.36 | 월계관 있으면 y=370 · 없으면 가로 중앙 y=150 |
| 월계관·리워드(`Frame 6671` 등) | `H × 0.92` | 1.25 | 가로 중앙, y=90 |
| 패드 목업 `Desktop-dark` | 기존 패드에서 복제, **크기 그대로** | — | **x=124, y=800** (슬롯 화면 시작 = x287, y848) |
| 오버레이(카드·칩·시트) | `H × 0.85~0.95` | 1.15~1.3 | 컷별로 기준 폰과 같은 자리에 오게 |
| 하단 뱃지(New Design 등) | `H × 0.95` | 1.3 | 하단 붙임 |

- 5.5"를 기준으로 하면 fs0 가 100 이면 `H = 1.5`, 110 이면 `H = 1.36`(6.5"와 같음)이다. **숫자를 외우지 말고 매번 fs0 를 읽는다.**
- 오버레이의 **세로 위치**는 기준 폰 화면 안에서의 위치를 패드 화면에 옮긴다:
  `y_pad = 848 + (y_폰 − 폰화면top) × k` — `k = 3.0846 / (폰UI폭 / 360)`(파생 함수와 같은 배율).
  가로는 프레임 중앙 기준으로 맞추고, 화면 밖으로 삐져나오는 카드는 왼쪽 여백 ≥ 40 을 지킨다.

- 헤드라인이 끝나는 곳이 y≈735 라서 목업 y=800 이면 겹치지 않는다.
- 오버레이가 위에 쌓이는 컷(05 알림 등)은 목업을 내린다(05 는 y=1480).
- 프레임에 `exportSettings = [{format:'PNG', contentsOnly:true, constraint:{type:'SCALE', value:1}}]`. **섹션에는 걸지 않는다.**

## 2. 앱 UI 만들기 — 컷 유형별

기준 폰 화면 슬롯 안을 열어 보고 셋 중 하나로 분류한다.

| 유형 | 판별 | 처리 | 26Y3Q-Renewal 해당 컷 |
|---|---|---|---|
| **A. 오토레이아웃 UI** | 최상위 프레임 `layoutMode` 가 VERTICAL/HORIZONTAL | **3장 파생 함수**로 1720×2406 생성 | 01 루틴탭 · 02 타임라인 · 03 분석 · 04 타이머 · 06 루틴 설정 · 발견탭 · AI(MCP) |
| **B. 절대배치 화면** | `layoutMode: NONE` (홈 화면·잠금화면) | 부품을 꺼내 패드 화면에 **직접 재배치** | 05 잠금화면 알람 · 07 홈 위젯 |
| **C. 기기 여러 대 합성** | 기준 폰 안에 이미 태블릿+폰/워치가 있음 | 기준 폰 속 태블릿을 `1799 / 그 태블릿 폭` 배로 키우면 **기존 패드 목업과 같은 크기**가 된다 (6.5"는 1282 → ×1.403) | 워치 컷 2개(`_08_aos`) |

### B 유형 예시
- **홈 위젯(07):** 배경 이미지를 1720×2406 사각형에 `scaleMode:'FILL'` 로 채우고, 위젯 6개를 `rescale(1.12)` 해서 **3열×2행 격자**로 놓는다(간격 50, 위 여백 230).
- **잠금화면(05):** 배경 위에 `Date`·`Time` 을 `rescale(1.3)` 해서 가로 중앙에 둔다. 벨 띠·푸시·라이브 액티비티는 프레임 위에 따로 얹는다.

### C 유형 예시
- 태블릿: x=-230, y=1260 (기준 폰처럼 왼쪽이 잘리게)
- 워치·폰: `rescale(1.4)`, 오른쪽 아래에 붙이고 **높이의 85% 정도만** 보이게
- All Device 띠: `rescale(1.3)`, y=740

## 3. 파생 함수 (A 유형) — 그대로 복사해서 쓴다

```js
// 기준 폰(6.5" 또는 5.5") UI(오토레이아웃) → 패드 1720×2406
// k: 360 기준 → 패드(ihp 3.0846) 배율. 폰 UI 폭이 무엇이든 맞춰 준다.
const al = x => x.type==='FRAME' && x.layoutMode && x.layoutMode!=='NONE';
function derivePad(ui, keepHeight = false) {
  let c = ui.clone(); if (c.type === 'INSTANCE') c = c.detachInstance();   // ⚠️ 4장 참고
  c.rescale(3.0846154 / (ui.width / 360));

  // ① 늘리기 전에: 부모 안쪽 폭을 꽉 채우던 자식을 기록
  const spans = new Set();
  for (const p of [c, ...c.findAll(al)]) {
    const inner = p.width - p.paddingLeft - p.paddingRight;
    for (const ch of p.children)
      if (ch.layoutPositioning !== 'ABSOLUTE' && 'resize' in ch && Math.abs(ch.width - inner) < 3
          && (p.layoutMode === 'VERTICAL' || p.children.length === 1)) spans.add(ch.id);
  }
  // ② 폭만 1720 으로
  const ST = 1720 / c.width;
  c.resize(1720, keepHeight ? c.height : 2406);

  // ③ 위에서 아래로: 가로 패딩·가로 간격을 늘리고, 기록한 자식은 새 안쪽 폭으로
  (function walk(p) {
    if (!al(p)) return;
    p.paddingLeft *= ST; p.paddingRight *= ST;
    if (p.layoutMode === 'HORIZONTAL') p.itemSpacing *= ST;
    const inner = p.width - p.paddingLeft - p.paddingRight;
    for (const ch of p.children) {
      if (spans.has(ch.id) && ch.layoutSizingHorizontal !== 'FILL') {
        if (ch.type === 'TEXT') ch.layoutSizingHorizontal = 'FILL';
        else { const sv = ch.layoutSizingVertical; ch.resize(inner, ch.height);
               if (al(ch) && sv === 'HUG') ch.layoutSizingVertical = 'HUG'; }
      }
      if (al(ch)) walk(ch);
    }
  })(c);
  c.name = ui.name + ' — iPad';
  return c;
}
// 사용: 슬롯을 비우고 넣는다
// for (const ch of [...slot.children]) ch.remove();
// const p = derivePad(ui); slot.appendChild(p); p.x = 0; p.y = 0;
```

- **세로로 스크롤된 화면**(분석처럼 화면보다 긴 UI)은 `keepHeight = true` 로 만들고
  `p.y = ui.y * k` 로 기준 폰과 같은 스크롤 위치를 맞춘다. 남는 부분은 슬롯이 잘라 준다.
- 기준 폰에서 UI를 위로 올려 둔 컷(06 루틴 설정)은 패드에서도 `p.y` 를 음수로 준다(-230).
  하단 시트에 가려지는 중요한 줄이 보이게 하려는 것이다.
- 가로 캐러셀 카드(발견탭 배너)처럼 **원래 화면 폭보다 좁은 카드**는 늘어나지 않는다. 의도된 동작이다.

## 4. 함정 — 전부 실제로 당한 것

| 증상 | 원인 | 대처 |
|---|---|---|
| 일정 패널이 안 늘어남 | 고정 폭 카드가 화면 폭이 아니라 **부모 안쪽 폭**과 같아서, 단순 FILL 규칙에 안 걸림 | 3장 ①번(안쪽 폭 기준 기록) |
| 패널이 오히려 **쪼그라듦** | 부모가 HUG 인데 자식을 FILL 로 바꿈 → 서로를 기다리며 최소 폭으로 수렴 | FILL 대신 **위에서 아래로 `resize(inner)`** (3장 ③번) |
| 영어였던 문구가 **한국어로** 돌아감 (타이머·워치) | 인스턴스를 `detachInstance()` 하거나 복제·크기변경할 때 **텍스트 오버라이드 소실** | 원본과 복제본의 TEXT 를 **수동 재귀로 같은 순서로 모아** `characters` 를 다시 넣는다. 대입이 무시되면 그 중첩 인스턴스를 detach 후 재대입 |
| `findAll` 결과가 0개 | 방금 clone 한 서브트리는 `findAll` 이 놓친다 | **수동 재귀**(`n.type==='TEXT'` + `'children' in n`)로 모은다 |
| `rescale` 에서 폰트 에러 | Pretendard·SF Pro 미설치 | **복제본에서만** 같은 굵기의 Montserrat 로 바꾼 뒤 rescale. 원본은 건드리지 않는다 |
| 배경에 **한국어 문구**가 보임 | 겹쳐 있던 이미지 레이어 중 하나가 **한국어 잠금화면 캡처**였다 | 한국어 검사는 TEXT 만 본다 → **스크린샷으로 눈으로 확인** |
| 노란 배경이 회색으로 나옴 | 기준 폰 배경이 이미지 여러 장을 MULTIPLY·LUMINOSITY 블렌드로 겹쳐 만든 색 | 기준 폰 렌더에서 색을 실측해 그라디언트로 다시 그렸다(`#EDE380→#FCF390` + 밝은 물결 `#FFF7A6`·`#FFF9C0`). 원본 이미지가 있으면 그걸 쓴다 |
| 오버레이로 엉뚱한 카드가 복제됨 | `findOne(name.startsWith('Card /'))` 가 UI 안의 카드를 먼저 찾음 | 오버레이는 **프레임 직속 자식(또는 지정 그룹의 자식)**에서만 찾는다 |
| 응답이 깨짐(SSE 에러) | 반환값이 커짐 · 이름에 이모지 | 카운트 위주로 반환, 이름은 `[^\x20-\x7E가-힣]` → `?` 로 치환 |
| 이름으로 찾던 노드가 `null` | 디자이너가 편집 중 (섹션 이름·ID 변경) | 매 호출 이름·크기로 다시 찾는다 |

## 5. 검증 — 끝내기 전에 이 넷

1. **스크린샷을 컷마다 본다.** 고정 높이 박스 넘침·배경 이미지 속 문구는 수치로 안 잡힌다.

   (오버라이드 소실·잘못 복제한 노드가 여기서 잡힌다.)
   ```js
   function texts(n, acc){ if (!n.visible) return acc; if (n.type==='TEXT') acc.push(n.characters.trim());
     else if ('children' in n) for (const c of n.children) texts(c, acc); return acc; }
   const A = new Set(texts(src65, [])); const extra = texts(pad, []).filter(t => !A.has(t)); // → []
   ```
3. **잔여 한국어 0** (영문 섹션이면). 숨김 레이어는 제외하되, 조상까지 `visible` 을 확인한다.
4. **프레임 11개 · 전부 2048×2732 · 섹션 겹침 0.**

## 폰 사이즈끼리 맞추기 (6.5 ↔ 5.5)

패드와 달리 폰끼리는 **폰 목업을 그대로 쓴다.** 비율만 다르다(6.5" 0.46 · 5.5" 0.5625).

| 방향 | 가로 맞춤 배율 | 결과 | 할 일 |
|---|---|---|---|
| 6.5 → 5.5 | 1242/1320 = **×0.941** | 1242×2699 → **약 490px 넘침** | 헤드라인–목업 간격을 줄이고, 아래쪽에 붙은 요소(떠 있는 카드·워치·라이브 액티비티)만 컷별로 다시 놓는다 |
| 5.5 → 6.5 | 1320/1242 = **×1.063** | 1320×2347 → **약 520px 모자람** | 목업을 아래로 늘려 더 보여 주거나(화면 아래쪽이 더 드러남) 헤드라인–목업 간격을 넓힌다. 잘려 있던 UI 아래쪽이 새로 보이므로 **그 부분 내용을 확인**한다 |

- 헤드라인은 두 사이즈 모두 2줄 고정 박스다. fs 가 바뀌면 줄바꿈이 달라질 수 있으니 스크린샷으로 확인한다.
- 리뉴얼판 5.5" 행은 프레임이 `1320×2208` 로 만들어져 있다(스토어 규격 1242×2208 과 다름). 기준으로 쓰기 전에 폭부터 확인한다.
