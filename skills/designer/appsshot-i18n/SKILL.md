# 앱스크린샷 다국어 대응 규칙 (현행 디자인 26Y3Q)

> 원본은 `routinery-v2` 레포의 `.claude/rules/appsshot-i18n.md`. 여기 사본은 대시보드 공개용이라 Figma 파일키와 사내 링크를 플레이스홀더로 바꿨다.

> 이 문서는 **지금 디자인의 구체값**(섹션 ID·프레임명·문자열)을 담는다.
> 디자인이 개편되면 무효가 되므로, 그때는 `routinery-v2 · .claude/rules/i18n-principles.md` 의
> 절차를 따라 이 문서를 새로 쓴다.

App Store / Play Store 스크린샷(앱스샷)을 한국어·영어 외 언어로 펼칠 때의 규칙.
Figma 파일 `[Growth] 앱스크린샷 디자인_v26` = `<FIGMA_APPSSHOT_FILE_KEY>` (파일키는 사내에서 확인).

## 원칙 3줄

1. **의미의 원본은 한국어.** 기획 의도가 한국어 섹션에 있다.
2. **영어는 골격·레지스터 참고용.** 문장 구조(주어·동사)와 톤을 빌려오되, **영문 마스터를 한국어에 맞춰 고치지 않는다.**
3. **한국어·영어 섹션은 직접 관리한다 → 자동화 대상이 아니다.** 건드리지 말 것.

> 결과적으로 타언어 섹션은 영문 마스터와 문구가 갈라진다. **이건 버그가 아니라 의도된 상태다.**

### 탐지 — 구조 서명 + 내용 스크립트

```js
// ① 앱스샷 언어 섹션의 구조 서명으로 후보를 거른다 (지금: 폭 30597 · 자식 6)
//    다른 용도 섹션(원본 UI 등)은 폭·자식 수가 달라 여기서 빠진다.
// ② 섹션 안 TEXT 를 표본으로 읽어 문자 체계로 언어를 판정한다.
//    findAllWithCriteria 는 인스턴스 내부를 놓치므로 수동 재귀로 모은다.
function texts(n, acc, cap) {
  if (acc.length >= cap) return acc;
  if (n.type === 'TEXT') { acc.push(n.characters); return acc; }
  if ('children' in n) for (const c of n.children) { texts(c, acc, cap); if (acc.length >= cap) break; }
  return acc;
}
const SCRIPT = {ko:/[가-힣]/, kana:/[぀-ヿ]/, han:/[一-鿿]/, ar:/[؀-ۿ]/};
const DIA = {vi:/[Ạ-ỹĂăƠơƯư]/, pl:/[ąćęłńśźż]/i,
             de:/[äöüß]/i, fr:/[àâçéèêëîïôùûœ]/i, es:/[áíóúñ¡¿]/i, pt:/[ãõ]/i};
const STOP = {en:['and','your','the','you','with','for','start','day','make','every'],
              id:['dan','yang','untuk','kamu','bisa','setiap','hari','buat','jadi','saat']};
```

판정 순서 — **위에서 먼저 맞는 것으로 확정**한다.

| 조건 | 언어 |
|---|---|
| 한글 비율 ≥ 15% | **ko** (의미 원본) |
| 가나 ≥ 5% | ja |
| 한자 ≥ 10% (가나 없음) | zh |
| 아랍 문자 ≥ 5% | ar |
| vi/pl/de/fr/es/pt 분음부호 최다 | 해당 언어 |
| 분음부호 없음 + `en` 불용어 다수 | **en** (골격 참고) |
| 분음부호 없음 + `id` 불용어 다수 | id |

> **vi·pt 는 분음부호가 fr/es 와 겹친다.** 반드시 `vi > 다른 전부`, `pt` 는 `ã/õ` 로 판정한다.
> **en 과 id 만 분음부호로 못 가른다** → 불용어 빈도로 가른다.

## 작업 순서 (컷 단위로)

컷마다 아래를 반복한다. 섹션 하나를 통째로 돌리지 말 것 — 컷 단위가 검수 가능한 최소 단위다.

1. **한국어 컷에서 의미를 읽는다.** 무엇을 약속하는 문장인가.
2. **영어 같은 컷에서 골격을 읽는다.** 주어가 누구고 동사가 무엇인지, 명령형인지 서술형인지, 레지스터가 캐주얼한지.
3. **대상 언어로 카피를 쓴다.** 번역이 아니라 재작성이다. 한국어 어순도 영어 어순도 따라가지 않는다.
4. **한국어 의미와 어긋나면 한국어가 이긴다.** 영어가 다른 말을 하고 있으면 영어를 버린다.
5. 자수·줄바꿈 제약(아래)을 확인하고 Figma에 넣는다.

## 문구 분류별 규칙

### ① 헤드라인 — 재작성

- 박스는 `textAutoResize: NONE`, **2줄 고정**. 5.5" w≈1100 h222 @fs100 / iPad @fs140~150 / 6.5" @fs120.
- 한 줄 자수 안전선: **CJK 9~10자**, **로마자·아랍어 ~20자**. 넘치면 3줄이 되어 목업을 덮는다.
- 직역 금지. 명사형 압축(한국어 습관)을 그대로 옮기면 어느 언어든 딱딱해진다.
- 3개 행(5.5"/iPad/6.5")에 **같은 문구**가 들어간다.

### ② 앱 화면 속 문구 — 번역하지 말고 인용

앱을 찍은 부분이므로 새로 번역하면 스크린샷과 실제 앱이 어긋난다. `origin/dev` 기준으로 값을 가져온다.

우선순위: `src/assets/translations/<lang>/<lang>.json` → `<lang>_habits.json`(key/desc, ko와 **인덱스가 같다**) → `recommend_todolist.json`·`recommend_sample.json`·`taglist.json`(12개 언어 컬럼 인라인).

**작업 브랜치가 뒤처져 있으면 옛 문구가 섞인다 → 항상 `git show origin/dev:...` 로 확인.**

앱 사전에 없는 것(샘플 루틴 이름, 발견 탭 카테고리 = 서버 `tagName`, 격려 문구)만 직접 번역하고, 무엇을 새로 지었는지 보고한다.

### ③ 영문 고정 — ⚠️ 실행 전 반드시 재확인

> **디자인이 바뀌면 이 목록이 통째로 무효가 된다.** 뱃지가 없어질 수도, 종류가 늘 수도,
> 번역 대상으로 정책이 바뀔 수도 있다. **아래를 그대로 적용하지 말고 매 실행마다:**
>
> 1. 조상 노드(`Badge_subtitle` · `Frame 6671` · `Rewards`)가 **지금도 있는지** 확인한다.
>    없으면 이 절은 무효 — 현재 구조를 다시 읽어 목록을 새로 만든다.
> 2. 찾은 노드 수와 문자열 목록을 **작업자에게 보여주고 "전 언어 영문 유지 맞나" 확인받는다.**
> 3. 바뀐 게 있으면 **이 문서를 먼저 고치고** 작업에 들어간다.
>
> 확인 없이 적용하면, 번역해야 할 문구를 영문으로 되돌려 놓고 끝난다.

한국어 섹션만 이 두 가지가 한글이다. 그런데 한/영 섹션은 건드리지 않으므로, **실무에서는 "뱃지류는 전부 영문"으로 외우면 된다.**

- **페이지별 요약 뱃지**(아이브로우, `Badge_subtitle` 하위) — 8종
  `Timer` / `Planner` / `Schedule` / `Widgets` / `All Device` / `Discover` / `New Feature` / `Recommendation`
- **리워드 뱃지**(수상 월계관, `Frame 6671` · `Rewards` 하위)
  `2026 App Store · Editor's choice` / `Total Users · 5 Million+` / `Apple 2026 · Apps To Support Those With ADHD · Best Self Care App`
  (행에 따라 `2025 App Store` · `Apple 2024` · `Best ADHD App` · `Best Self-Care App` 이 섞여 있다 → 아래 "원본 드리프트" 참고)
- 판정은 문자열이 아니라 **조상 노드 이름**으로 한다. 헤드라인 위치로 판정하면 헤드라인 없는 프레임의 월계관을 놓친다.
- 사전에서 빼면 안 된다 — 사전엔 넣어 번역하고 **마지막에 이 라벨 노드만 영문으로 되돌린다.** 그래야 앱 화면 속 같은 단어(`Discover` 등)가 번역된 채로 남는다.
- 2026-09-17 확인: Ja · Ar · Pl 섹션은 두 뱃지 모두 이미 영문 상태다. 새로 건드리지 말 것.

### 원본 드리프트 — ⚠️ 실행 전 실측하고 확인받을 것

> **아래 표는 2026-09 스냅샷이다. 디자인이 바뀌면 값도 자리도 달라진다.**
> 그대로 믿고 통일하면 디자이너가 의도적으로 다르게 둔 값을 덮어쓴다. 매 실행마다:
>
> 1. 한/영 섹션에서 **같은 자리 문구를 사이즈 행별로 실제로 읽어** 표를 새로 만든다.
> 2. 갈린 게 있으면 **작업자에게 보여주고 "어느 값으로 통일할지" 정한다.**
>    통일하지 않기로 하면 그대로 두고 그 사실을 보고에 적는다.
> 3. 통일은 **한/영 섹션을 관리하는 쪽이 먼저** 한다. 타언어에서 손대지 않는다.

영문 마스터·한국어 모두 같은 자리에서 값이 갈린다. 타언어 섹션은 마스터를 clone 한 것이라 **같은 드리프트를 그대로 물려받았다.**

## 언어별 주의

- **ar**: 앱이 `I18nManager.allowRTL(false)`라 아랍어도 LTR로 렌더된다. **스크린샷도 LTR 유지.**
- **pl**: `rutyna`는 "지루한 반복"의 부정 뉘앙스가 있다. 앱스샷 카피엔 `nawyki`(습관)를 쓴다.
- **de**: `Tipp`은 "조언"으로 읽힌다. 탭 제스처는 `Tippen`.
- **id**: 앱스샷은 캐주얼 레지스터(`bikin`, `beneran`)로 일관한다.
- **ja/zh**: 명사형 `〜を管理` / `管理你的〜` 는 시스템 용어다. 소비자 카피에 쓰지 않는다.

## Figma 작업 함정

- 폰트는 **Montserrat**. Pretendard·SF Pro 일부는 MCP 환경 미설치 → 내가 편집하는 노드만 Montserrat 동일 웨이트로.
- `findAllWithCriteria`는 **INSTANCE 내부와 방금 clone한 서브트리를 놓친다** → 텍스트 수집은 수동 재귀(`n.type==='TEXT'` + `'children' in n`).
- 중첩 라이브러리 인스턴스 깊은 곳은 `characters` 대입이 **조용히 무시된다** → 대입 직후 `n.characters === newValue` 검증, 실패분은 디자이너에게 보고(인스턴스 교체 필요).
- `use_figma` 응답이 **약 20KB를 넘으면 SSE가 깨진다** → 40~60개 단위로 잘라 반환. astral 이모지(🌅📚🧹)는 코드포인트로 이스케이프.
- 에러가 나면 그 호출의 변경이 **전부 롤백된다.** "이어서 채우기" 금지, 처음부터 다시 실행.
- 새 섹션은 원본 clone 후 **간격 3000 이상**. 900이면 옆 섹션 자식으로 빨려 들어간다.
- 파일은 디자이너가 동시 편집 중이다. 시작 전에 원본 TEXT 노드 수를 먼저 확인할 것.
